# Automation

CI validates the app and produces App Store screenshots. **It does not build, sign, or upload
anything** — distribution is done locally, from a machine whose keychain already holds the
certificates.

That scope is deliberate, and it is what makes the whole pipeline verifiable: no App Store Connect
API key, no match repository, no distribution certificate, and **no repository secrets of any kind**.

| Command | What it does |
|---|---|
| `bundle exec fastlane test` | Build and run the full suite on iPhone, iPad, and macOS |
| `bundle exec fastlane ios screenshots` | Capture real simulator screenshots and compose the branded store images |

Inside Claude Code, `/appstore-assets` runs the screenshots lane and then verifies the output by
looking at it.

---

## Workflows

| Workflow | Trigger | Runs | Artifacts |
|---|---|---|---|
| `ci.yml` | push to `main`, pull request | tests on iPhone / iPad / macOS | result bundles, **on failure only** |
| `release.yml` | `v*` tag, manual dispatch | `fastlane test` → `fastlane ios screenshots` | `appstore-images-<run>`, `raw-captures-<run>` |

Cutting a release is therefore: **validate everything, then produce the store images.** Roughly 20
minutes of macOS runner time, which is why it is not on every push.

### Getting the screenshots

`Actions → Release → Run workflow`, or push a `v*` tag. When it finishes, download
**`appstore-images-<run>`** — that zip is what goes to App Store Connect. `raw-captures-<run>` holds
the unbranded captures and is only useful for diagnosing a bad composite.

Both artifacts use `if-no-files-found: error`: a lane that reports success while producing nothing
fails the run. Silence is not success — that exact failure mode (3 of 8 files, exit 0) has happened
here before.

`AppStoreAssets/` is git-ignored. CI regenerates it from real simulator captures every run, so it
cannot go stale.

## Screenshots

| Path | What |
|---|---|
| `fastlane/Snapfile` | devices, locales, launch arguments, status-bar override |
| `iBaseUITests/ScreenshotUITests.swift` | one test per screen — navigation and capture only |
| `Scripts/generate_appstore_assets.swift` | branding: background, eyebrow, headline, device inset |
| `build/screenshots/` | raw captures |
| `AppStoreAssets/` | finished store images |

Two devices, chosen so a **native capture already equals an accepted App Store size** — nothing is
ever rescaled:

| Simulator | Native | Family |
|---|---|---|
| iPhone 17 Pro Max | 1320 × 2868 | iPhone 6.9" |
| iPad Pro 13-inch (M5) | 2064 × 2752 | iPad 13" |

**Verified 2026-08-03** against Apple's screenshot specifications: only **iPhone 6.9"** and
**iPad 13"** are mandatory; App Store Connect derives every other size. Re-check if a year has
passed — these requirements change.

Runs are deterministic: `-ShowcaseData` seeds an in-memory store and a throwaway defaults suite,
`-UITestScreenshotMode` disables animations, and the status bar is pinned to 9:41 / full battery /
full signal.

## Distribution is local

Uploading to TestFlight or the App Store is done from Xcode's Organizer, or by adding lanes back if
that ever becomes routine. The certificates live in the developer's keychain; nothing is shared with
CI.

### If the Mac app is ever shipped

The macOS entitlements and Hardened Runtime settings were **removed** along with the distribution
lanes, since nothing used them. Shipping the Mac app will need them re-added:

- **Mac App Store** — `com.apple.security.app-sandbox` is mandatory; the store rejects any app
  without it.
- **Developer ID direct download** — `ENABLE_HARDENED_RUNTIME = YES` is mandatory; Apple refuses to
  notarize without it, and the error it returns is unhelpfully generic.

The two are **not interchangeable**. A Developer ID certificate cannot authorise App Store-only
entitlements (App Groups, iCloud containers), and signing an App Store-shaped entitlements file with
one produces a binary the kernel kills at launch — a failure that looks like a crash, not a signing
problem.

## Known gaps

- **No automated macOS screenshots.** `snapshot` drives XCUITest against simulators, and macOS has
  none. Mac store images must be captured by hand.
- **Single locale.** The app is not localized; `en-US` is the honest maximum. Adding locales before
  localizing the app produces identical English images under different locale folders.
- **`AppStoreScreenshotUITests` is superseded** by `ScreenshotUITests` but still present. It captures
  three stale screens into a temp directory nothing reads.
